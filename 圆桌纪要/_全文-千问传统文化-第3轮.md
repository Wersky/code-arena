## A · 朝代终极裁决

**(a) 消解了——而且面试官的这条论据反过来打他自己的锁元方案。**

他的原话针对的是"洪武废团茶后瀹饮法当道，候汤三沸失真"。但第 2 轮我已经把核心从宋的击拂、咬盏换成**三泡递减**，候汤降级为一张修饰卡。三泡递减是**洪武之后才存在的机制**：宋点茶碾末调膏、一巡而尽，根本没有"第二泡"。所以真正失真的是宋——他若锁宋，我这条机制当场作废；他若锁元，元代茶书稀薄到他自己都要设"候选人举证"的门槛。锁明则三泡递减有直接出处：许次纾《茶疏》"一壶之茶只堪再巡，初巡鲜美，再则甘醇，三巡意欲尽矣"（**引文需面试前复核原文**），这就是一泡香、二泡醇、三泡淡的原始表述。反驳成立：这条论据杀的是旧版本，不是新版本。

**(b) 不直接打击锁明——因为它打的是配色层，我锁的是朝代层，两者能分开。**

他的判断在**纸面**上完全正确：青花蓝是釉下钴蓝，纸绢上没有青花，把钴蓝画到卡框、面板、终端上就是介质用错。这一点我全盘接受，第 2 轮后我的纸面配色已撤成墨、朱、淡赭。但"朝代"与"配色"是可分离的两个变量：立绘里那把**青花执壶是立体瓷器**，画它用钴蓝天经地义；而明代正是青花最盛的一朝（永宣成化）。所以结论是：**锁明、不锁明青花当纸色**，青花只留在器物与立绘这一件东西上。他把"配色用错"正确识别出来了，却推出"所以朝代不能是明"，这一步不成立。

**(c) 总成本：锁明 1.9 人日、锁元 2.7 人日、锁宋 4.2 人日，取小者是明。**

拆开算：

- **锁明** = 机制改 `sts_combat.gd` 0.5d + 立绘局部重出（欧式荷叶边发带、蕾丝披肩，edits 局部）0.4d + 纸面装帧（卡框 0.45d、面板 0.5d）1.0d = **1.9d**
- **锁元** = 机制必须推翻回到宋式火候 0.5d（并丢掉许次纾原文支撑）+ 立绘**全重出**：立领盘扣是明制，元服要改交领右衽，躯干重画加切件重做 1.2d + 背景重画 0.5d（视觉总监第 2 轮核出桌面是**明式高型家具**有束腰直棂，素绢立轴盛于明清）+ 装帧术语 0.5d = **2.7d**，另附"元代茶书自证"的考据风险
- **锁宋** = 2L+2M ≈ **4.2d**

差的不只是 0.8 天，是"现成背景是明式"这条埋伏：锁元要连茶室一起重画。

> **(d) 最终组合：明代（洪武废团茶后的瀹饮）＋ 一套器物（青花执壶、盖碗、茶盏）＋ 一套配色（纸面墨、朱、淡赭，青花只给器物与立绘）＋ 一个机制（三泡递减：一泡香、二泡醇、三泡淡、四泡水味，换茶重置）。**

## B · 机制最终形态

**1. 一句话规则**：她的茶只经得起三泡——每出一张牌就过一泡，二泡最醇、三泡发淡、四泡只剩水味；打一张「换茶」把泡数拨回一泡，代价是一个能量和一个牌位。

**2. 数值表**（`scripts/core/sts_combat.gd`）

| 项 | 值 | 落点 |
|---|---|---|
| 新增状态 | `var brew := 0`（0..3，跨回合不清） | 文件头变量区 |
| 档位加成 | `const BREW_STEP := [0, 4, -3, -6]` | 插在 `_play_card_impl:454` 的 `step`/`slot` 同一处加法里 |
| 攻击下限 | `v = maxi(1, v)`（防四泡归零卡死） | 同上，仅 ATTACK 分支 |
| 推进 | 数值牌结算后 `brew = mini(brew + 1, 3)` | `_play_card_impl` 结算尾部 |
| 换茶 | `brew = 0`、`block += 3`、**不推进泡数** | 仿 `rice` 的早退分支（`:373` 同层），cost 1 |
| 跨回合 | `start_turn` **不减 brew** | `:259` 不加任何衰减行——这是与 DeepSeek 的分界 |
| 序列收尾 | `end_send` 不清 brew | `:528`（对照 `seq_streak = 0` 在 `:530`） |
| 关闭连段 | `var step := 0 if ai_id == "kweno" else STREAK_STEP * (seq_streak - 1)` | **两处同构**：`:454` 与 `preview_sequence:1033`，只改一处卡面就骗人 |
| 预览同构 | 影子推演从当前 `brew` 起步、逐张推进 | `preview_sequence:1005` |

**3. 与 DeepSeek 的结构差异**：DeepSeek 的 `seq_streak` 每次 `end_send` 清零，奖励只活在"一次发送"里；千问的 `brew` 跨回合不清、单调不可逆，只能靠一张牌主动拨回——一次性连段 vs 可重置的衰减周期。

**4. 手牌拖拽：砍掉，换成「排序模式·点两张交换」。**

诚实评估：拖拽本身没那么贵（`sts_card_view.gd` 已有 `gui_input`，加三个信号约 25 行；`arena.gd` 加换位与重排约 50 行），真实成本 0.75d 而非 2-3d。但它会踩三个坑：拖动中 `_layout_hand` 动画与悬停同时触发、点击与拖拽的阈值判定、换序后 `can_play` 因 `hand[0]` 变化必须整表刷新。**半成品拖拽比没有拖拽更糟。**

砍掉后机制不会退化，因为**决策内容与手势无关**——只要玩家能改顺序，无论拖还是点，都是同一个"把最重的牌放到二泡"。退化只发生在"完全不改顺序"的那种情况：那时机制塌成"每三张自动换一次茶"，玩家每回合只剩一个决定。所以替代方案必须保留改序能力，只是换手势：**排序模式 = 复用现有弃牌模式那套开关**（`arena.gd:153` 的 `_discards_left`、`:2257` 的 `_discard_mode` 分支照抄），开模式→点第一张→点第二张→`combat.hand.swap(a,b)` + `_hand_views.swap(a,b)` + `_layout_hand(true)` + `_update_seq_preview()`，关模式。改动集中在 `arena.gd` 一个文件三个函数，**不碰 `sts_card_view.gd`**，0.25d。

**5. 三十秒自检：能感知，但必须靠预览先演算出来。**

你若一进战斗就打三张牌，数字是 6 → 10 → 3，肉眼能看出先涨后崩，但看不出**为什么**。真正让机制在 30 秒里自己说话的是：`preview_sequence` 已经把每张牌的预计数值写在卡面上（`sts_card_view.gd:366 set_seq_value`）。把 `brew` 接进预览后，玩家**还没按发送**，四张牌上就是 6/10/3/0，点一下换序，数字立刻重排——不用试玩、不用教程，看一眼就懂。所以必做的是两件：预览接 brew（两处 guard 同构）+ 手牌上方一条四段茶汤条（`_play_card_impl` 每推进一段点亮一段，水色由深转浅）。茶汤条 0.15d，是 P0 里的必需品；没有它，规则只能活在我的嘴里。

## A · 朝代终极裁决

**(a) 成立，而且它确实否掉了我第 1 轮的方案，我承认。** 第 1 轮我把卡框写成「米白 `#F3EDE1` / 青花蓝 `#2E5A8F` / 朱印 `#A8323A`」——青花蓝落在纸面上，正是我自己说的介质用错。第 2 轮我改成墨加赭，其实已经在自我修正，但没承认第 1 轮是自相矛盾。现在承认：**纸面不能有钴蓝**。修正不是放弃蓝，是换蓝：元代纸本用**花青**（靛蓝制的国画颜料），浅绛山水（黄公望）就是赭石 + 花青 + 墨。钴蓝在釉下合法，花青在纸面合法，视觉同调、谱系不同。

**(b) 元代纸面语汇比宋更丰富，不是妥协。** 三样：**浅绛**（赭石 + 花青淡彩，元人成熟）、**渴笔干擦**（倪瓒）、**长题**（赵孟頫"书画同源"后，元人开始在画心上方题长跋）。墨 + 朱 + 赭完全成立——朱是印不是设色；元代文人画钤印已普及，手卷、立轴在元代都成立（倪瓒《容膝斋图》1372 存世），面试官第 2 轮已替这一点背书。纸面配色：墨 `#1B1B1B` / 花青 `#3A5A78` / 赭石 `#A8763E` / 朱 `#A8323A`，纸 `#E8E2D4`（元纸偏灰黄，不是宣白）。装帧：卡框用**元代书叶（蝴蝶装半叶，元承宋制，版框高宽比约 1:1.4–1.5，与 150×226 同形）**；面板用**立轴**（297×555 = 1:1.87，竖长对，手卷是横的）。这两个术语元代都成立，不用改成明清。

## 分歧 A · 朝代终极裁决

**(a) 我不接受这个反驳。**

「三泡递减」不是把宋的术语换成明的术语，它**换掉了决策结构**。原机制是「可升可降 + 双端惩罚 + 复位阀」：水太冷伤害不足，水太老自伤，`续水` 把温度拨回去——玩家每回合要判断的是「这回合烧到几沸就收」。三泡递减是**严格单调递减**：一泡最香，越往后越淡，最优解恒为「把最重的牌摆第一张」，然后从左到右打完。它没有「该不该现在烧」的判断，只有「快点花掉」的执行。策划自己把它概括成「不可逆消耗」，那它就是倒计时，不是看火。

更要命的是这条自我矛盾：他 P0-3 报价 2–3 天的「手牌拖拽重排」，存在的前提是**峰值会移动**（要算准第三张进三沸）。换成递减后峰值恒在第一张，顺序不再需要玩家安排，拖拽重排直接变成多余功能。**他的 P0 正在推翻他的 P0。**

另外那句「具体引文面试前需复核原文」——三泡递减的出处是清代闽粤工夫茶的俗谚路数，不是明代瀹泡的成文规矩。我一句「出自哪本书哪一句」，这条论据当场落地。锁明不是换术语，是拿一条有原文的判据（鱼目／涌泉连珠／腾波鼓浪）去换一条没核实的，同时丢掉击拂／咬盏／沫饽三张最像工序的卡。

**(b) 元代纸面配色，我自己回答。**

视觉总监说得对：青花蓝是釉下钴蓝，只活在立体瓷器上；纸绢上是墨、朱、花青、赭石，把 `#2E5A8F` 那种饱和亮蓝画到纸上就是介质用错。元纸是麻纸／竹纸／皮纸本色，**灰黄**，不是宣白。定死一套：纸底 `#E3D9C6`（陈化偏 `#D9CEB8`）／松烟墨 `#1C1A17`（暖黑，不是纯黑）／朱砂印 `#A03A2C`（元代印泥偏橘，不是 `#C8102E` 大红）／花青淡染 `#41586A`（低明度低饱和）。**青花蓝只允许出现在立绘那只执壶的釉面上**，且必须有高光——釉面才有高光，纸没有。这一条本身就是「我知道介质差别」的现场证据。

**(c) 最终推荐：锁元。但理由要换。**

成本摆平：锁明 M+S≈1.2–1.8d，且要弃三张有原文的卡、换一条未核实的引文；锁宋 2L+2M≈3.5–4d，在 5 人日预算里是算术上不可能，不是性价比问题；锁元 S+S+立绘边际 0.5d≈1.0d。

**改变我立场的两条**：① 我撤回「改 3 处最便宜」这个理由——那是成本取舍不是考据取舍，正是我第 2 轮用来打策划的那把尺子，不能自己不用；② 我接受介质论，青花蓝撤出所有平面载体。

**坚持的**：决策结构判据（可升降双端惩罚 ≫ 不可逆递减），以及它带出的第二后果——递减会让拖拽重排变成废功能。

改成事实交集后，锁元这句话才立得住：**元是「点茶还没死、青花已成熟」的唯一交集**。团茶要到洪武二十四年（1391）才罢造，元代点茶合法，所以击拂／咬盏／沫饽三张卡在元全部成立——策划以为必须弃掉的，锁元全保住了。锁明才是那个要弃卡的方案。

## 分歧 B · 机制最终形态验收

**1. 30 秒能感知吗？能感知，但感知错了东西。**

递减的倍率玩家一秒就懂，但他懂到的是「早打」，不是「怎么排」。候汤必须补两样：火候条要显示**下一张的倍率预览**（「下一张 ×1.3」），不是只显示当前档位；首回合脚本化起手，强制让第 3–4 张是大牌，让「顺序有意义」这件事在 30 秒内发生一次。否则 30 秒试玩只留下「数字在涨」。

**2. 拖拽重排：不必做，但「顺序可改写」必须做。**

`_on_send_pressed()` 的注释和代码写得很清楚——「整手牌按从左到右的顺序一张张打出，`hand[0]` 就是最左那张」，`_rebuild_hand()` 里 `_hand_views` 与 `combat.hand` 严格同序。也就是说**执行序列就是手牌下标**，改顺序 = 交换 `combat.hand` 两个元素 + `_layout_hand(true)` + `_update_seq_preview()`。`sts_card_view.gd:232` 的 `_on_gui` 只有左键 `clicked` 和右键 `flip`，没有拖拽——所以拖拽是**新增交互**，不是必须的管道。

判定：**「点两张换位」0.5 人日，必须做；拖拽 2–3 天，可以不做。** 若连 0.5d 都没有，退路是把机制改成「卡面自述条件」（仅三沸时 +4），顺序交给匹配而非编排——机制仍成立，但降级成资源匹配，我会在面试里问出来。

**3. 5 人日分配**：崩点修复 0.4d ／ front-hi 产出 0.5d ／ 机制 1.5d ／ 顺序交换 0.5d ／ 卡牌 0.75d ／ 美术 1.0d ／ 缓冲 0.35d = **5.00d**。

**4. 一条硬判据（现在基线是 0，可真验）**：

```bash
# 机制：文化术语必须出现在「数值分支」里，而不是只出现在卡名
grep -n "咬盏\|击拂\|沫饽\|水老" scripts/core/sts_combat.gd   # 要求 ≥3 命中
grep -c "brew" scripts/core/sts_combat.gd                      # 基线 0，要求 ≥8

# 皮肤：同一批词如果只出现在卡池，就是贴图
grep -rn "咬盏" scripts/ | grep -v sts_card_pool.gd
```

判据一句话：**术语出现在 `if` 的条件里 = 机制；只出现在 `name` 字段里 = 皮肤。** `水老` 必须在 `sts_combat.gd` 里作为自伤分支存在，不能只在卡面描述里出现。
