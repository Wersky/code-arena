## 最终方案：千问 · 元代点茶 × 候汤机制

### 一句话
千问的母题是**元代点茶**——把唐宋人「看水」的老规矩做成她每回合要判断的火候：水越烧越开，打重了会自伤；打一张「续水」把温度拨回一沸。青花只留在她手里那只执壶的釉面上，纸面是灰黄皮纸配墨、朱砂、花青。

### 为什么是元代（三朝裁决的结果）
| 方案 | 美术返工 | 机制返工 | 总成本 | 裁决 |
|---|---|---|---|---|
| 锁宋 | 立绘重画1.5d（立领盘扣非法）+茶室背景0.5d+器物0.5d+卡框面板0.5d | 0 | ≈3.0d | 否——宋无青花，唯一一张立绘与茶室全废 |
| **锁元** | 立绘局部0.5d（蕾丝软帽→包髻簪钗、披肩→披帛）+器物0.3d+背景0.3d+术语0.1d | 0（末茶未绝） | **≈1.2d** | **采纳** |
| 锁明 | 立绘局部0.5d+器物0.2d+背景0 | 三泡递减+起手十张替换+重跑模拟=2.6d | ≈3.3d | 否——要弃三张有原文的卡（击拂/咬盏/沫饽），换一条未核实的引文 |

**元是唯一交集**：团茶要到洪武二十四年（1391）才罢造，元代点茶合法；青花在元代才成熟（景德镇至正型）。所以击拂、咬盏、沫饽三张最像工序的卡在元代全部成立。

### 机制：候汤（`scripts/core/sts_combat.gd`）
一句话：**她的水会越烧越开——连续出牌升温加伤，烧过头就「水老」打折还自伤；打一张「续水」把水温拨回一沸。她不是在爬阶梯，是在看火。**

| 项 | 值 | 落点 |
|---|---|---|
| 状态 | `var brew := 0`（0..4），倍率 `[0.8, 1.0, 1.3, 1.3, 0.6]` | 文件头 |
| 推进 | 数值牌结算后 `brew += 1` | `_play_card_impl:454` 结算尾部 |
| 水老 | `brew >= 4` 本张结算后自伤 1 | 同上 |
| 冷却 | `start_turn`: `brew = maxi(0, brew - 1)` | `:259` |
| 不清零 | `end_send` 不清 `brew` | `:528`（对照 `seq_streak=0` 在 `:530`） |
| 关连段 | `var step := 0 if ai_id=="kweno" else STREAK_STEP*(seq_streak-1)` | **两处同构**：`:454` 与 `preview_sequence:1033` |
| 预览同构 | 影子推演从当前 `brew` 起步 | `preview_sequence:1005` |

**与 DeepSeek 的结构差异**：DeepSeek 的 `seq_streak` 每次 `end_send` 清零，奖励只活在「一次发送」里；千问的 `brew` 跨回合不清、可升降、只能靠一张牌主动拨回——一次性连段 vs 可复位的水温周期。

**辅助**：沫饽（`brew` 停在 2..3 时 `end_send` 加 block +2）、茶末（主动弃牌攒末，3 末→下一张攻击 +5）。
