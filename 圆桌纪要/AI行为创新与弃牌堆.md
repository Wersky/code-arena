- **成员**：玩法设计师（大胆创新派）｜AI 行为设计师（涌现性派）
- **轮次**：2 轮（收敛终止）
- **状态**：completed

## 第 1 轮 · 诊断与方案

### 【玩法设计师】
**为什么像脚本**：
1. 动作语义全是数值加减（伤/防/能/易伤/嘲讽），结果可被玩家算术推完，第 20 回合最优线已知，「选择」退化成噪声——可预测即脚本感。
2. 决策与表达分离：LLM 只贴台词，玩家看不到「它在想什么」的证据。
3. 没有玩家模型：常量表对谁都一样，感受不到「被针对」，只剩打木桩。

**方案**：
- A 读牌反制：每 3 回合把玩家近期出牌序列喂给 LLM（复用战斗日志，不加请求），输出「预测意图 + 反制动作 + 挑衅句」，猜中给本地常量表固定加成档。玩家套路是开放集合，脚本枚举不完。
- B 私人心愿：开局 LLM 用预设 DSL 生成「本局私人胜利条件」，本地校验谓词合法性、奖励锁常量表档位。
- C 虚张声势：TAUNT 升级为「宣告下回合动作」，可真可假，玩家花资源识破；说谎贴合局势才有效。

### 【AI 行为设计师】
**判定标准**：行为分布随交互历史而变，且变因可被玩家看见；LLM 产出的是「理由」而非「词」，本地只做校验。

**三案评级**：
- A 够 AI 的前提成立——但若反制仍由本地规则选、LLM 只写台词，就是脚本加配音。必须让 LLM 输出「我猜你下一手 X，因为 Y」，本地校验 Y 是否引用真实历史。
- B 最够 AI——改的是目标函数而非数值；但开局随机生成只是随机性不是智能，心愿须由玩家历史或上局败因推出，且过程中要泄漏信号。
- C 不够 AI——脚本随机真假即可，除非真假取决于对玩家识破率的建模（记得上次被识破→这次说真话）。

**关键补充**：①跨战斗记忆（战后玩家行为指纹存本地 → 下局开局注入并强制引用）；②败后自省（输了自己加一条新规则进策略库，从 3 个本地候选选 1 并说理由）。

**主持人纪要**：共识=光换台词没用、LLM 产出必须带可校验理由、跨局记忆/自省才是 AI 特质；分歧=C 够不够 AI、B 心愿来源；结论=第 2 轮聚焦「读牌反制+跨局记忆+败后自省」最小落地形态。

## 第 2 轮 · 落地形态与验收

### 【玩法设计师】
- **读牌反制**：开战气泡一行「我读你：上局连出 2 防御 → 这次先破防」+ 敌方对应牌红描边；每场 2 次（首回合预告、触发回合执行），演出 ≤2 秒。
- **跨局记忆**：战前静态徽章「笔记本：你上次靠连段赢我」；每场 1 次，0 秒演出，为反制铺垫因果。
- **败后自省**：玩家赢后弹 1 次 3 选 1 小窗，AI 选 1 条规则 + 一句理由，可一键跳过；战斗内 0 演出。
- **总预算**：战斗内 ≤2 秒/场，战斗外 1 次点击。
- **弃牌堆**：改成「本场已用牌」账本——显示累计打出张数，洗回抽牌堆时不清零，点开看历史列表。

### 【AI 行为设计师】
- 评分七成，仍露三处脚本痕迹，补丁全采：
  ① 读牌落空**必出「读错」气泡并回写账本**，允许「读不出你」；
  ② 笔记本徽章挂**时效+次数**（上次/已 3 局），换打法须过期；
  ③ 自省改为**候选只给败因锚点，规则 LLM 自写**，本地只校验引用+去重。
- **AI 味验收线**：①引用——每句含 ≥1 本局事件 ID（回合+牌+数值），不过不渲染；②分布——历史 A/B 读牌目标 KL 散度 > 阈值；③纠错——落空必产纠错文本并回写，静默判失败。

**主持人纪要**：共识=三件套成立+补丁全采+弃牌堆改账本；预算已压到战斗内 ≤2 秒/场。

## 综合方案（可直接落地）

### 一、三个机制
1. **读牌反制（AI 的「读心」）**
   - 战后把玩家行为指纹（攻击/防御/发育比例、最近连段、常用组合）写本地存档；
   - 战斗首回合：单次请求让 LLM 输出「预言：你这局会 X，因为 Y」+ 本局反制策略；Y 必须引用真实历史事件锚点（回合+牌），本地校验；
   - 每场 2 次触发（首回合预告 + 触发回合执行），气泡 ≤2 秒 + 敌方牌红描边；
   - 猜中（玩家行为落入预言）→ 敌方该动作吃本地常量表固定档加成；**猜错必须说「读错」并回写**（AI 会认错，这本身是 AI 味）。
2. **笔记本（跨局记忆）**
   - 玩家的历史（上局胜负原因、连段峰值、常用流派）存 run 存档；
   - 战前徽章「笔记本：你上次靠连段赢我（第 3 局｜已 2 次）」带时效（3 局过期）；
   - 下局 LLM 强制引用一条。
3. **败后自省**
   - 玩家赢后，LLM 从败因锚点里选 1 条 + 自写一条新规则（本地校验引用锚点 + 去重），可跳过；下局生效。

### 二、弃牌堆 bug（已诊断）
- 根因：每回合补牌 `refill_from_deck()` 把弃牌堆全部洗回抽牌堆并 `clear()` → 显示恒为 0（设计语义 ≠ 玩家心智）。
- 修法：改成「本场已用牌」账本——`StsCombat` 加 `played_total`（累计打出，洗回不清零），图旁数字显示它；牌堆面板点开显示本场打出牌列表。战斗逻辑零改动。

### 三、验收线（写进 smoke）
1. 每句读牌/记忆/自省台词必须含 ≥1 个本局事件 ID 锚点，否则回退模板且不算 AI 台词。
2. 读牌落空必须产出纠错文本并回写账本（静默落空判失败）。
3. 弃牌堆账本：打出 3 张后显示 3，洗回后仍显示 3（回归）。
4. 断网/超时：三件套全部静默回退（无气泡、无加成、账本不写）。

### 四、未被采纳
- C 虚张声势：行为设计师判「脚本也能做」，本轮不做。
- B 私人心愿：留作二期（需解决「心愿来源必须是历史而非随机」）。

### 五、遗留
- 读牌目标的 KL 散度阈值需实测标定。
- 笔记本跨局数据放 user:// 还是 run 存档（影响换角色/新周目）。
- 自省规则库上限与去重策略。

## 附：弃牌堆 bug 独立说明

- **现象**：弃牌堆数字一直显示 0。
- **根因**：`sts_combat.gd::refill_from_deck()` 每回合 `discard_pile.clear()` 把牌洗回抽牌堆（T5 为修「卡组循环锁定」特意改成全牌堆采样），所以弃牌堆天然长期为空。
- **修复方向**：显示层改「本场已用牌」累计账本（不改战斗逻辑，不破坏 T5 设计）。
