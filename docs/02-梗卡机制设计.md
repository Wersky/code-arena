## 0. 一句话

**把"提示词工程"换成"梗卡连携"：牌是梗，连携是梗，AI娘是梗的主题加成——一个没玩过的人，扫一眼就知道这两张卡放一起会发生什么。**

---

## 1. 为什么换掉旧机制

旧机制是「命令行 + 顺序层 + 39 条规则 + 口味表」：判定链太长、术语太多，
第一次玩的人要背 39 条规则才知道为什么少了几分。新机制把一切压成一句：

> **打出这几张卡 → 触发这个梗 → 分数这么变。**

规则总数从 39 降到 **24 条连携**，且每条都有一个能笑出声的名字。

旧机制（`scripts/core/scoring.gd` 的顺序层、`scripts/core/ai_taste.gd`、
`scripts/data/card_data.gd` 的 `cli_*` 字段）**全部保留不动**，新机制平行存在，本轮由界面层切换使用。

## 2. 术语表

| 术语 | 含义 |
|---|---|
| **梗卡** | 一张牌。只有 id / 名称 / 类型 / 基础分 / Token 消耗 / 梗注解，没有命令行参数。 |
| **类型（kind）** | 饭 / 代码 / 玄学 / 杂项 / 专属。决定卡的颜色与哪些连携会理它。 |
| **连携（combo）** | 一组牌放在一起触发的"梗"。有名字、有效果、一眼能懂。 |
| **×2 / ×3** | 连携要求的牌数（如 rice ×2 表示两张白米饭）。 |
| **专属卡** | 只有指定 AI娘 主题下才能打出的牌（4 张大肥鱼专属牌）。 |
| **主题（theme）** | 一位 AI娘 的偏好：给某一类卡的**基础分**加成（倍率或固定分），并解锁专属卡。 |
| **base / flat / mult** | 计分三要素，见 §6。 |

### 5.3 命中规则

- 一条连携的**所有**要求牌都在本回合手上，才算命中（`and` 关系，不是 `or`）。
- `×2` / `×3` 是**牌数**要求：手上必须有 2 张 `rice`、3 张 `printf`。
- 专属牌参与的连携（`c_free` / `c_binge` / `c_salary` / `c_dive` / `c_buffet` / `c_hotpot_binge`）
  **只在 DeepDeek 主题下可能命中**——其他主题下专属牌被引擎剔除，连携自然不成立。
- 一条连携每回合**最多命中一次**。
- 多个连携可同时命中，效果**全部叠加**（倍率相乘、加分相加、类型倍率相乘）。

## 6. 计分公式（只有这一条）

```
base  = Σ (卡基础分 × 主题倍率 × 连携类型倍率) + Σ(所有卡 +N 分)
flat  = Σ 连携的加分          # 可为负，如「刷屏」−40
mult  = Π 连携的倍率
score = round((base + flat) × mult) − 惩罚
```

- **主题倍率**：该 AI娘 主题给这张卡的**基础分**倍率（见 §4）。
- **连携类型倍率**：饭类/代码类/玄学类卡各自的倍率（见 §5），只作用于该类型卡的**基础分**。
- **所有卡 +N 分**：加在每张卡的基础分上（`c_overflow` 的 +10）。
- **惩罚**：Token 超预算的部分，每点 12 分。Token 预算默认 **9**。
- **整数计分**：所有对外数值都是 int；中间量用 float，算完 round。

### 6.1 结算顺序（引擎实现顺序）

1. **剔除专属卡**：非归属主题下的专属卡不参与任何计算（`result["blocked"]` 列出）。
2. **判定连携** → `result["hits"]`（每项含 `combo_id` / `name` / `desc` / `effects`）。
3. **汇总效果**：类型倍率相乘、加分相加、全局倍率相乘、抽牌数、Token 增减、手牌变化。
4. **逐卡基础分**：`基础分 × 主题倍率 × 类型倍率 + 主题固定分 + 所有卡加 N`，
   再处理"下一张触发两次"（该卡本回合得分 ×2，可叠加）。
5. **Token 与惩罚**：`c_hit` 命中则本回合 Token 消耗为 0；`c_catch` 留下的免罚盾抵消本回合惩罚。
6. **总分**：`round((base + flat) × mult) − 惩罚`，下限 0。

### 6.2 跨回合状态（`carry`）

有些连携的效果落在"下一回合"，引擎把它们放进 `result["carry"]`，由界面层存下来、
下一回合再传回 `ctx["carry"]`：

| carry 字段 | 含义 | 来源连携 |
|---|---|---|
| `next_mult` | 下一回合总倍率 | `c_stuck`（×1.3） |
| `penalty_shield` | 下一回合惩罚归零 | `c_catch` |
| `hand_limit_delta` | 手牌上限累计变化 | `c_overflow` / `c_salary`（各 −1） |
| `hand_delta_next` | 下一回合手牌张数变化 | `c_binge`（−1） |
| `token_budget_delta` | 下一回合 Token 预算变化 | `c_hot_cache`（+1） |

### 9.1 一处需要明确的口径

**DeepDeek 的「饭类卡基础分 ×1.3」只作用于 `kind = 饭` 的 4 张通用饭卡**
（白米饭 / 馒头 / 火锅 / 干饭人），**不作用于 4 张专属卡**——专属卡的 `kind` 是「专属」，
与主题表里写的"饭类卡"是严格按类型字段判定的。4 张专属卡本身就是深蓝鱼的形象牌，
基础分（20 / 18 / 17 / 15）已经高于通用牌，不再叠加倍率。
若后续要让专属牌也吃 ×1.3，改 `MemeCard._build_themes()` 里 deepdeek 的
`bonus_kinds` 为 `[Kind.FOOD, Kind.EXCLUSIVE]` 即可（引擎已支持多类型加成）。
