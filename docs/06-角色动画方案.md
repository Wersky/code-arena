# 06 · 角色动画（序列图）怎么搞

> 结论先放这：**别用"一次出 N 张关键帧"的方式做动画**。Q 版像素角色的走路、摆动这类动作，
> 90% 应该用「切件 + 变换」在引擎里算，剩下 10% 的复杂演出才值得走「视频 → 抽帧」。

---

## 1. 为什么按帧生图最亏

以一条 8 帧走路循环为例：

| 项 | 数字 |
|---|---|
| 生图次数 | 8 次（每帧一次） |
| 单次耗时 | 本仓库管线实测 **22~45 秒**（`gpt-image-2.5-1k`） |
| 一次性成功率 | 大概 1/3 —— 帧间配色、发丝、衣褶几乎必然漂移 |
| 实际次数 | 8 × 1.5~3 次重抽 ≈ **12~24 次** |
| 人类还要做的 | 逐帧修边、对齐脚底、统一调色板 |

**根本问题**：图像模型没有"上一帧"的概念。它每次都在独立地"重新想象这个角色"，
所以帧与帧之间不是"同一张画在动"，而是"八张不同的画"。这个不一致**没法靠提示词解决**，
只能靠人修——而修 8 帧的时间，够你把角色切成件、绑上骨骼、自己加关键帧了。

---

## 2. 三条路线（2026 年的现状）

### 路线 A：切件 + 骨骼／变换（**本仓库首选**）

把一张立绘切成 头 / 躯干 / 上臂 / 前臂 / 腿 / 尾巴 等部件，每个部件一个节点，
用旋转 + 位移 + 缩放做动画。走路、摆动、呼吸、受击、欢呼、点头——全部覆盖。

- **引擎侧**：Godot 用 `Skeleton2D` + `Polygon2D`（带骨骼权重），或者更简单——
  部件就是一堆 `Sprite2D` 父子层级，`AnimationPlayer` 直接 K 旋转。
  Q 版不需要网格形变，**父子层级 + 旋转就够**。
- **成本**：一次性切图（每个角色 30~60 分钟，纯手工/半自动），之后 **0 边际成本**、
  **0 闪烁**、参数随便调、换配色不用重出图。
- **上限**：柔性形变（裙摆飘、长发甩）做不了，得靠分片。Q 版通常不在意。

### 路线 B：视频 → 抽帧 → 像素锁定（复杂动作才用）

1. **图生视频**：把角色立绘喂给视频模型，提示词写明
   `locked camera, full body visible, flat solid bright green background, seamless loop`
   常用模型：Wan 2.2 / 3.0、Kling 3.0、Seedance、Veo。（一次生成 = 一条动画，不是一帧）
2. **抽帧**：`ffmpeg` 按固定帧率抽 PNG，或浏览器端工具
   （[loopsprite](https://loopsprite.com/)、[Sprite Smithy](https://www.spritesmithy.com/guide)
   都是纯本地、免费、不上传）。
3. **抠背景**：绿幕 chroma key + 边缘侵蚀（去掉绿边晕）。
4. **像素锁定（关键）**：逐帧独立量化会让同一块阴影在不同帧变成不同颜色，
   播放时像"沸腾"一样闪。必须**整段共用一份调色板**再量化，并做时间稳定性处理
   （Spriteomatic 叫 `Pixel Lock`，Sorceress 的 True Pixel 叫"共享调色板"）。
5. **打包**：等宽等高对齐 → 图集 + JSON 元数据 → 引擎切成 `SpriteFrames`。

- **成本**：每条动画 1 次视频生成 + 几分钟本地处理。
- **坑**（都踩过的人写的）：脚滑、循环接缝、绿边、帧率与游戏帧率不匹配（抽帧率必须 = 播放帧率）。

### 路线 C：买现成的像素专用工具

| 工具 | 能干什么 | 价格 | 备注 |
|---|---|---|---|
| **PixelLab** | 骨架动画 + 文字生成动画 + 4/8 方向旋转，直接导 sprite sheet | $12~50/月 | **有 MCP server / API**，可以被 AI 直接调用；动画上限 128×128 |
| **Retro Diffusion** | 出静止像素图最"真"（真像素网格），动画只在网站/API | $65 一次性 | 适合出底图，不适合出动画 |
| Spine / DragonBones | 专业 2D 骨骼，工业标准 | $69 / 免费 | 要自己绑骨；比 Godot 内建强，但多一层导入 |

**2026 年公认最省的组合**：Retro Diffusion 出底图 → PixelLab 出旋转/动画 →
引擎里再手修 1~3 帧（预备动作、打击帧、跟随动作）。

## 3. 成本对照（按本仓库实际管线算）

| 方案 | 一次性 | 每条动画 | 4 角色 × 3 动作 | 质量风险 |
|---|---|---|---|---|
| 按帧生图 | 0 | 8~24 次生图（≈6~18 分钟） | **96~288 次生图** | 帧间不一致，必须人修 |
| 视频→抽帧 | 0 | 1 次视频 + 5 分钟本地 | 12 次视频 | 像素沸腾、脚滑，需要锁定 |
| **切件+变换** | 每角色 30~60 分钟 | **0** | **一次性 2~4 小时** | 无闪烁，但柔性形变受限 |
| PixelLab | $12/月 | 一次点击 | 12 次点击 | 需手修，128px 上限 |

## 4. 本项目的建议（分级）

这个游戏的角色是 **192×256 的 Q 版全身**（`assets/art/ai-*.png`），比例是"头大、身体小"，
正是最适合切件的体型。

| 动作 | 用什么 | 理由 |
|---|---|---|
| 待机呼吸、上下浮动 | **纯代码变换**（已有一版 `CardView._bob_y`） | 零成本，永远不会崩 |
| 摆动 / 摇头 / 点头 / 惊讶 | **切件 + 旋转**（头一个节点就够） | 一个头节点能演出 80% 的情绪 |
| 走路 | **切件 + 2~4 帧腿部循环**（腿可以只画 2 张，左右互换） | Q 版腿短，2 帧就够读 |
| 攻击 / 受击 | 切件 + 位移/旋转 + 特效贴片 | 主要靠特效，不靠帧 |
| 必杀 / 变身 / 舞蹈 | **视频 → 抽帧** | 唯一值得花视频模型的场景 |

**第一步只做一件事**：给 4 个 AI 娘做一套「切件 + 头节点 + 2 帧腿」的骨架，
写一个 `ChibiRig` 节点，对外只暴露 `play("idle" | "walk" | "shake" | "attack")`。
之后所有界面（选人、对局、结算）复用同一套，不再产生任何生图成本。

## 5. 落地步骤（我们这边可以直接做）

1. 写 `tools/cut_rig.py`：把立绘按"切件模板"切成 head / torso / arm_l / arm_r / leg_l / leg_r，
   输出每个部件的 PNG + 锚点 JSON（锚点 = 该部件的旋转轴心，比如头的轴心在脖子上）。
   半自动：先按包围盒粗切，再让主人/我用一张遮罩图微调。
2. 写 `scripts/ui/chibi_rig.gd`：读锚点 JSON，生成节点树，`AnimationPlayer` 里放 4 个动作。
3. 目检：`--shot=rig` 出一个"4 动作 × 4 帧"的拼图，一眼看动作对不对。
4. 视频路线留成工具：`tools/video_to_sheet.py`（ffmpeg 抽帧 + 共享调色板量化 + 对齐打包），
   等真需要"必杀演出"时再用。
