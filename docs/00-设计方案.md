# 《提示词擂台 Prompt Arena》设计方案

> 2D 肉鸽 · 纯鼠标操作 · 对标小丑牌（Balatro）的构筑与关卡结构
> 主题：你是"提示词工程师"，闯关方式是给一个需求写出高质量的提示词（Prompt），让模型输出通过评测线。

---

## 0. 一句话

**把小丑牌的"打牌组牌型"换成"拼装提示词组件"，把"小丑牌道具"换成"各家大模型的性格化增益"。**

---

## 1. 为什么不做横版动作

主人明确不要 WASD。本作 100% 鼠标：点手牌 → 落进槽位 → 点运行 → 看结算。
所有操作都是"点"，没有位移、没有瞄准、没有连招。乐趣来自**构筑决策**（我这手牌该怎么排、这关要不要赌一张风险卡），而不是操作精度。

---

## 2. 核心循环（一局 = 一个 Run）

```
主菜单
  ↓
【选择你的ai】── 选 1 位核心 AI 娘（DeepDeek 初始可选，其余 3 位随通关解锁）
  ↓
┌──────────────── 战斗（一场 Benchmark）────────────────┐
│  抽 8 张梗卡手牌（牌库洗牌，含该主题的专属卡）          │
│  ↓                                                   │
│  点 ≤5 张 → 梗卡离手 → 控制台流式打出梗名             │
│  ↓  实时语法条：✓ 语法正确 / ✗ while 后面必须接 if   │
│  点"运行"                                             │
│  ↓                                                   │
│  结算：(base+flat) × mult − Token 惩罚                │
│  语法不合法 → 只给最少基础分（每张卡 1 分）           │
│  弃掉打出的牌，补满手牌，回合 +1                      │
│  ↓                                                   │
│  回合用尽：累计分 ≥ 目标分？                          │
│    是 → 过关 → 三选一奖励（AI 道具 / 卡牌强化）       │
│    否 → 失败 → Run 结束（可重开）                     │
└───────────────────────────────────────────────────────┘
  ↓
过关 → 三选一奖励 → （每 3 关）商店 → 下一关
  ↓
失败 → 重打本关（AI 道具保留）/ 放弃本局
L10 通关 → 整局结算 → 主菜单
```

**没有关卡选择界面**：关卡是线性的 L1→L10，按顺序闯。
每通关 3 关进一次商店（用算力点买卡 / 买道具 / 刷新货架）。

**一次 Run 的长度**：约 20-30 关，40-60 分钟，和小丑牌一个量级。

## 3. 卡牌 = 提示词组件

> ⚠️ **本章的"牌型堆叠"已被 3.3 的命令行式提示词机制取代**。
> 3.1 的牌型表降级为**组件加成层**（仍然算分，但不再是分数的主因）。
> 顺序才是分数的主因 —— 详见 3.3。

一张卡 = 提示词里的一个**组件**，6 种类型（对应颜色）：

| 类型 | 含义 | 举例 | 基准分 | Token |
|---|---|---|---|---|
| **角色 PERSONA**（青） | 你是谁 | 资深工程师、毒舌评论家、法务顾问 | 12 | 1 |
| **任务 TASK**（金） | 做什么 | 写个函数、抓出这个 bug、生成一段 SQL | 18 | 2 |
| **素材 KNOWLEDGE**（蓝） | 依据什么 | 贴上代码仓库、附上报错堆栈、实时搜索结果 | 14 | 2 |
| **格式 FORMAT**（紫） | 怎么呈现 | 输出一段 JSON、用表格呈现、分步骤说明 | 10 | 1 |
| **范例 EXAMPLE**（橙） | 少样本示范 | 给一个正例、给三个反例、给一组问答对 | 16 | 1 |
| **约束 CONSTRAINT**（绿） | 边界在哪 | 不得编造事实、不超过 100 字、拒绝回答不知道的 | 10 | 1 |

另有一类**风险卡**（跨类型的正交标记）：臆造 API、跳过验证直接给结论、把不确定当确定的。
基础分高（20-26），但命中会吃惩罚 —— 这是全局最紧张的一格。

> **槽位不绑定类型**（**旧机制，已被 3.3 取代**）：旧版 5 个槽是自由槽，牌型由"打出的卡的类型多重集"决定，
> 与摆放顺序无关，预览面板还会按规范顺序重排。新版**没有槽位**，**顺序由玩家自己决定且直接决定分数**。

### 3.1 牌型表（Combo）—— **组件加成层，已被 3.3 降级**

> 这张表**不再是主玩法**，只作为新机制里的一层加成参与计算。
> 同样 6 张牌、同样命中这些牌型，顺序对错能差 **429 分**（1228 vs 799）——差在 3.3 的顺序层，不在这里。

牌型全部由类型多重集推导，命中多个则**倍率相乘、加分相加**。

| 牌型 | 触发条件 | 倍率 | 附加 |
|---|---|---|---|
| 堆叠 | 同类型 ≥ 3 张 | ×1.15 | 该类型每张 +15 分 |
| 委托明确 | 有 任务 + 角色 | ×1.10 | +30 |
| 结构化输出 | 有 格式 | ×1.10 | +20 |
| 范例驱动 | 有 范例 + 任务 | ×1.15 | +25 |
| 接地 | 有 素材 | ×1.05 | +15 |
| 受控 | 有 约束 | ×1.10 | 约束卡基础分 ×2 |
| 深度推理 | 任务 + 范例 + 约束 | ×1.20 | +40 |
| 完美配方 | 5 张且 5 个不同类型 | ×1.50 | +100 |
| 幻觉 | 打出风险卡 | ×1.40 | −70（可被护盾抵消） |

**计分公式**（**旧机制**；新机制的完整公式见 3.3.2）

```
基础分 base  = Σ 卡基础分（含道具修正）
加分  flat  = Σ 牌型加分 + Σ 道具加分
倍率  mult  = Π 牌型倍率 × Π 道具倍率
Token 花费 = Σ 卡 token
超预算罚  = max(0, Token花费 − 本关预算) × 15
最终分 = round((base + flat) × mult) − 超预算罚 − 幻觉罚
```

### 3.2 手感校验（蒙特卡洛实测）

用 `tools/balance_sim.gd` 跑 120 次完整 Run（每关贪心取最优组合），实测数据：

- 单回合得分：3 张普通组合 ≈ 110；4 张 ≈ 180；5 张全不同类型 ≈ 890。
- "完美配方"是刻意设计的 jackpot —— 起始牌组里 **范例 卡只有 1 张**，前期几乎拼不齐，必须靠奖励/商店拓宽牌库才成立。
- 每关目标分 ≈ 该关贪心均分的 **60%~70%**，这条比例线是全部关卡数值的锚点。

> **踩过的坑**：最初把目标分按"400 → 9000"拍脑袋递增，实测贪心每回合上限只有约 500 分，
> L9/L10 的目标分根本不可能达到，整局通关率 0%。
> 关卡数值必须由模拟器反推，不能手写。改用 `balance_sim.gd` 后曲线才成立。

### 3.3.1 机制总述

```
主菜单 → 【选择你的ai】→ 战斗界面 → 敲命令行 → 运行 → 结算 → 奖励 → 下一关
```

战斗界面的核心不再是"填 5 个槽位"，而是**敲一条命令行**：

- 抽 8 张手牌（牌库洗牌）
- **点手牌 → 该卡变成一段命令行参数 → 控制台"唰"地快速打字敲进去**
- 最多敲 **6 段**（第 7 段被拒，提示「命令行过长（最多 6 段）」）
- 点「▶ 运行」→ AI 娘按**你写的顺序和结构**回话 + 打印分数明细
- 弃掉打出的牌，补满手牌，回合 +1

**片段格式**固定为 `--<flag> "<值>"`，flag 由卡类型唯一决定：

| 卡类型 | flag | 例 |
|---|---|---|
| 角色 PERSONA | `--role` | `--role "资深工程师"` |
| 任务 TASK | `--task` | `--task "写个函数"` |
| 素材 KNOWLEDGE | `--knowledge` | `--knowledge "附上报错堆栈"` |
| 格式 FORMAT | `--format` | `--format "输出一段 JSON"` |
| 范例 EXAMPLE | `--example` | `--example "给一个正例"` |
| 约束 CONSTRAINT | `--constraint` | `--constraint "不得编造事实"` |

值默认 = 卡标题（`cli_token`，长度 ≤ 20 字符）。
命令行前缀 = 本局核心 AI 娘的 id（`deepdeek` / `kweno` / `chatppt` / `grock`）。

**顺序 = 玩家点击卡牌的顺序**，不自动重排。命令行本身就是展示与编辑区（不再有槽位行）。

### 3.3.2 顺序层评分模型

最终分公式（**flat_order 在乘法之外**是硬约定）：

```
final = maxi(0, round((base + flat_generic) × mult_generic × mult_order) + flat_order − 罚分)
mult_order 钳制 [0.50, 1.20]      # 规则层
道具层倍率叠在规则层之上（可达 1.20 × 1.08 = 1.296）
```

规则表共 **39 条**（23 条通用 `str_` + 16 条口味 `tas_`），命中多条时**倍率相乘、加分相加**：

| 类别 | 通用规则（示例） |
|---|---|
| 片段数 | `str_len_2`~`str_len_6`：2~6 段分别 +10/+14/+18/+22/+26（互斥，只命中相等那条） |
| 顺序质量 | `str_clean` 标准序 ×1.05 +15 ／ `str_one_swap` 一处错位 +5 ／ `str_messy` 两处错位 ×0.95 −12 ／ `str_scramble` 三处以上错位 ×0.88 −28 |
| 结构位置 | `str_role_head` 角色开篇 +8 ／ `str_no_role_head` 角色缺位 ×0.93 −16 ／ `str_task_anchor` 任务居中 +8 ／ `str_task_misplaced` 任务错位 −10 ／ `str_format_before_example` 格式先于范例 +6 ／ `str_constraint_tail` 约束收尾 +8 ／ `str_constraint_broken` 约束未收尾 ×0.95 −12 |
| 链路完整度 | `str_wide_chain` 要素种类 ≥5 ×1.08 +30 ／ `str_adjacent_task_knowledge` 任务素材相邻 +6 ／ `str_gap` 结构断裂 每处 −6（下限 −18） |
| 重复与长度 | `str_dup_flag` 同参数重复 ×0.92（重复每多一次再 −8，下限 −30）／ `str_compact` 命令行 ≤80 字符 +8 ／ `str_verbose` >120 字符 −10 |

**四个可复现算例**（`tests/verify_c4.gd` 是它的执行体，**必须逐字等于 1228 / 1045 / 799 / 113**）：

| 算例 | 命令行 | order_flat | order_mult | 总分 |
|---|---|---|---|---|
| 例1 标准序 6 段 | `--role … --task … --knowledge … --format … --example … --constraint …` | +133 | ×1.17936 | **1228** |
| 例2 角色任务颠倒 | `--task … --role …`（其余同例1） | +75 | ×1.044576 | **1045** |
| 例3 三处错位 | `--constraint … --format … --task … --role … --example … --knowledge …` | +4 | ×0.855800 | **799** |
| 例4 双 role 3 张 | `--role "资深工程师" --role "小学老师" --task "写个函数"` | +39 | ×0.966 | **113** |

> **无顺序层基线 = 929**。即：好结构 **+32.2%**，乱结构 **−14.0%**。
> 这是整个新机制的价值锚点 —— 同样的牌，顺序就是全部。

### 3.3.4 打字机交互时序

```
点手牌卡 A
  → run.add_command_part(frag_A)
  → console.type_in(frag_A)   ─┬─ 若此刻正在打字 → 先把未打完的那段【一次性补全】
                                └─ 然后才开始打 frag_A（逐字，每段归一到 0.6~1.2 秒）
点手牌卡 B（若 A 还没打完）
  → 【立刻补全 A】→ 命令行里永远不出现半截片段 → 接着打 frag_B
点命令行里的某一片段
  → console.finish_all() → 移除该片段（其后片段自动前移）→ 对应卡退回手牌
点「▶ 运行」
  → console.finish_all() → Scoring.evaluate(cards, {ai, command_parts}) → 打印结果
回合结束
  → run.command_parts.clear() → 控制台清空 → 手牌补满 8 张
```

**铁律**：任何时候命令行里都不许留半截片段（契约 H-3）。

### 3.3.5 道具层（`scope="item"`）

在 39 条规则表**之外**新增的第 40 条规则，叠在规则层**之上**：

| id | 名称 | scope | 条件 | 效果 | 归属 |
|---|---|---|---|---|---|
| `itm_gemigo_knowledge` | 多模态素材加成 | `"item"` | 命令行含 `--knowledge` 片段 | 顺序层倍率 **×1.08** | **Gemigo**（道具，不是 AI 娘） |

- 规则层倍率仍钳制 `[0.50, 1.20]`；道具层叠加以 → 持 Gemigo 时顺序层总倍率上限 `1.20 × 1.08 = 1.296`
- 同一 `effect_id` 叠 2 件只算一次，不重复乘
- 与口味规则不冲突：`tas_dd_grounded` 是 AI 娘维度，`itm_gemigo_knowledge` 是道具维度，可同时命中
- **实测**：6 段标准序 + DeepDeek：1228 → **1316**（+88 分，+7.2%）

> ⚠️ Gemigo 是**道具**，不是 AI 娘。它在 `scripts/data/ai_item_pool.gd`，
> 不在 AI 娘总表里、也没有形象资源。AI 娘与道具是两套东西，别混。

### 3.4 梗卡 + 连携机制（**牌组存档 · 计分已被 3.5 取代**）

> **契约唯一真值**：`docs/02-梗卡机制设计.md`（牌组表 / 24 条连携表 / 主题表 / 计分公式 / 吐槽台词库）。
> 本节是设计侧摘要，逐条规则与 API 签名以契约文档为准。
>
> ⚠️ **2026-10-21 起，连携不再是计分主体**。牌组、主题加成、Token 惩罚这些**全部保留**，
> 但"凑连携"换成了"**写成一段语法正确的程序**"（见 3.5）。
> `MemeCombo.evaluate()` 仍在仓库里（`scripts/core/meme_combo.gd`）作为存档，不参与结算。

#### 3.4.1 一句话（历史）

**把"写提示词"换成"打梗卡"**——卡面是**梗**（白米饭 / while / 递归 / 幻觉 / 大肥鱼…），
打出**成对的梗**就触发**连携**（无限续饭 / 米生米 / 套娃 / 扶墙出 / 涌现涌现…），
分数靠**凑连携**而不是靠排顺序。

#### 3.4.2 牌组（23 张）

- **通用 19 张**：饭类 4（白米饭 / 馒头 / 火锅 / 干饭人）、代码类 9
  （while / for / if / else / 递归 / try / catch / printf / 死锁）、
  玄学类 3（幻觉 / 温度 / 涌现）、杂项类 3（上下文 / 缓存 / token）。
- **专属 4 张**：大肥鱼 / 白米饭自由 / 暴食 / 深海鱼 —— **全部归属 DeepDeek 主题**，
  其他 3 个主题下**打不出来**（界面会拦，引擎也会拦）。
- 每张卡在牌库放 **2 份**（`RunState.MEME_COPIES`），因为连携需要同名卡凑对子，1 份永远凑不出来。
- 卡字段：`id / name / kind(饭·代码·玄学·杂项·专属) / base_score / token_cost / flavor(梗注解) / unique_owner`。

#### 3.4.3 连携（24 条）

分两类：**原 16 条**（吃干饭梗与编程梗的交叉）+ **新增 8 条**。

| 类别 | 例子 | 效果 |
|---|---|---|
| 纯增益 | 无限续饭（rice + while） | 饭类卡分值 ×1.4 |
| 纯增益 | 一饭两吃（rice ×2） | 饭类卡分值 ×2 |
| 纯增益 | 干饭自由（bigfish + rice） | 饭类卡分值 ×1.5 |
| 纯增益 | 双层循环（while + for） | 代码类卡分值 ×1.2，抽 1 张 |
| 纯增益 | 涌现涌现（emerge ×2） | 玄学类卡分值 ×1.5 |
| 固定加分 | 干饭人的干饭（foodie + rice） | +50 分，抽 1 张 |
| 固定加分 | 扶墙出（bigfish + binge） | +120 分，下回合少 1 张手牌 |
| 固定加分 | 扶墙火锅（hotpot + binge） | +150 分，抽 1 张 |
| 固定加分 | 馒头管够（mantou ×2） | +60 分，Token −1 |
| 固定加分 | 热缓存（cache + token） | +70 分，下回合 Token 预算 +1 |

#### 3.4.5 计分公式（唯一一条）

```
base  = Σ (卡基础分 × 主题倍率 × 连携类型倍率) + 连携的"所有卡加 N 分"
flat  = Σ 连携的加减分（可为负）
mult  = Π 连携的倍率
score = round((base + flat) × mult × 上回合倍率) − Token 惩罚
```

- Token 预算默认 9（每关 `level.token_budget` 覆盖），每张卡消耗自己的 `token_cost`，
  **每超 1 点罚 12 分**；「兜住了」可以抵消这一次惩罚。
- 「卡死」命中时本回合 **score = 0**，下一次结算 ×1.3。
- 分数尺度：单回合 **60~140 分**，整关（3~6 回合）**400~830 分**。
  ⚠️ 旧命令行机制是几千级，**两套刻度互不通用**。

#### 3.4.6 回合流程

1. 抽 8 张手牌（牌库 = 该主题可用的卡 × 2 份）
2. 点手牌 → 梗卡离手 → 控制台**流式打出梗名** → 凑成连携立刻**弹绶带横幅** + 播报
3. 每回合最多打 **5 张**（`RunState.MEME_HAND_LIMIT`），可撤回
4. 点「▶ 运行」→ `MemeCombo.evaluate()` 结算 → 打印分数明细 + AI 娘回应
5. 结算后 carry 写回（倍率 / 惩罚护盾 / 手牌上限增减 / Token 预算增减），
   抽牌类效果生效，未打出的牌与打出的牌一起进弃牌堆，补满 8 张，回合 +1
6. 回合用尽：累计分 ≥ 目标分 → 过关

### 3.5 代码语法机制（**当前唯一主玩法** · 2026-10-21）

> **契约唯一真值**：`scripts/core/code_program.gd`（`class_name CodeProgram`）。
> 本节是设计侧摘要，规则与 API 签名以代码为准。

#### 3.5.1 为什么改

主人的原话：

> 「这些都看不懂呀……把游戏的出牌改成真实代码架构吧，就比如现在 while, if 等代码词放一起
> 顺序不同就会错乱，让玩家不知道看什么。改成让**代码语句规则正确才算给分**吧，
> 如果没有就给最少的基础分。规则正确，然后再看语句类型，比如 **while 必须要接 if 来限制**等等。」

旧机制是「凑连携」——玩家只管把对子丢上去，**顺序没有意义**，所以
「while 和 if 挨在一起到底算什么意思」是纯噪音。现在改成**真的在写一段程序**：
牌的顺序 = 语句的顺序，顺序错了这段程序就跑不起来。

#### 3.5.2 语法规则（7 条，每条都有一句中文提示）

| # | 规则 | 中文提示（界面上原样显示） |
|---|---|---|
| R1 | `while` 后面**紧跟** `if` | while 后面必须接 if（用 if 来限制循环） |
| R2 | `if` 后面可以接 `else` | —（加分项，不报错） |
| R3 | `else` 前面必须有 `if` | else 前面必须有 if |
| R4 | `try` 后面必须出现 `catch` | try 后面必须接 catch |
| R5 | `catch` 前面必须有 `try` | catch 前面必须有 try |
| R6 | `for` 后面至少要有一条语句 | for 后面至少要有一条语句（循环体不能空） |
| R7 | `if` 后面至少要有一条语句 | if 后面至少要有一条语句 |

数据卡（饭 / 玄学 / 杂项 / 专属）**不是语句**，放哪都不影响语法，只提供基础分。

#### 3.5.3 计分（两条路，泾渭分明）

```
语法不合法 → 每张卡只值 1 分，不给任何加成与倍率（"最少的基础分"）
语法合法   → base  = Σ (卡基础分 × 主题倍率)
            flat  = Σ 结构加成（护栏 / 完整分支 / 异常兜底 / 退出条件 / 套娃 / 干饭大餐）
            mult  = Π 结构倍率
            score = round((base + flat) × mult) − Token 惩罚
```

- 语法错误全部列在控制台红字里（`✗ 语法错误：<规则中文提示>`）。
- **实时语法条**：每放/撤一张卡立刻重算并显示在命令行正下方：
  - 绿字 `✓ 语法正确 · 当前程序 N 分`
  - 红字 `✗ <规则提示>（还有 N 处）`
  这样玩家在**点运行之前**就知道这段程序合不合法，不用等到结算才发现。

#### 3.5.4 结构加成（语法合法之后才生效）

| 结构 | 触发条件 | 加成 |
|---|---|---|
| 护栏 | `while` 后紧跟 `if` | +25 flat ×1.15 |
| 完整分支 | `if` 后紧跟 `else` | +25 flat ×1.15 |
| 异常兜底 | `try` 后出现 `catch` | +35 flat ×1.2 |
| 退出条件 | `for` 后紧跟 `if` | +20 flat ×1.1 |
| 套娃 | 嵌套深度 ≥ 2 | +40 flat ×1.1 |
| 干饭大餐 | 饭类 ≥ 3 张 | +40 flat |
| 刷屏 | `while` 段里有 `printf` | ×0.9，Token −1 |

> **嵌套深度的例外**：`while` 紧跟的那个 `if` 是**护栏**，不是新的一层，不计入深度。
> （踩坑手册坑 33：早期把护栏算成一层，深度恒多 1，套娃判定全错。）

#### 3.5.5 分数尺度（换机制后整体腰斩）

| | 旧连携机制 | **新语法机制** |
|---|---|---|
| 单回合 | 60~140 分 | **40~120 分** |
| 整关（3~6 回合） | 400~830 分 | **158~420 分** |
| 全 10 关目标分 | 320~760 | **158~420** |

⚠️ 换机制后**必须重跑平衡模拟重校目标分**，不能沿用旧数字（踩坑手册坑 27）。

> 也就是说**当前关卡难度只由「回合数 + Token 预算 + 目标分」决定**。
> `rule_text` 目前也没有任何界面在显示它，所以不会误导玩家；
> 要给梗卡机制配专属规则，是下一轮的事（见「进度交接.md」的遗留清单）。

**规则设计的分寸**：规则只能**压分数**，不能**掐断能力上限**。
早期版本用"本关牌库中没有 角色/范例 卡"这种禁打规则，直接砍掉约 20% 的得分天花板，
导致目标分必须下调、曲线出现回退。改成"该类型基础分减半"后，牌型结构完整，天花板不变，曲线恢复单调递增。

**算力点**来源：过关时 `关卡回合数 × 15 + 超出目标分 ÷ 10`。
（早期版本按"剩余回合"算，但回合通常是被用完的，等于只给溢出分——打完第一关连一张卡都买不起。）

### 6.1 圆弧扇形

卡牌不放在容器里，而是挂在全屏 `card_layer` 上，坐标由圆弧公式算出：

```
a_i    = (i - (n-1)/2) / (n-1)/2 × ARC_MAX_ANGLE      # 每张的角度
pivot = (屏幕中点, 屏幕底 - ARC_BOTTOM - ARC_RADIUS)     # 圆心在屏幕下方
pos_i = pivot + (R·sin a_i, R·cos a_i)                  # 底边中点贴在弧上
```

- `ARC_RADIUS = 1150`、`ARC_MAX_ANGLE = 0.30`（≈17°）
- 卡以**底边中点**为支点（`pivot_offset`），旋转跟随弧线切线 → 像手里握着的一把牌
- 悬停：放大到 `1.16`、抬起 30px、旋转收到 55%（抬起来的同时摆正一点）
- 放进插槽：支点回中心、旋转归零、位置补间到槽位

### 6.2 像素风

- **字体**：方舟像素字体（Ark Pixel Font 12px，OFL-1.1，可商用可嵌入），
  关掉抗锯齿 / hinting / 子像素定位，并锁定 `fixed_size = 12` + 整数倍缩放 → 真正的像素字。
- **贴图**：全部走最近邻采样（`project.godot` 的 `default_texture_filter=0`），不糊。
- **控件**：全硬边，零圆角；按钮用 2px 描边 + 右下偏移 2px 的方块投影。配色限定 16 色以内。
- **立绘显示**：384px 的源图一律按整数倍显示（2× = 768），像素块不会不匀。

### 6.3 设计刻度（不许随手写数字）

| 刻度 | 值 | 说明 |
|---|---|---|
| 字号 | 12 / 24 / 36 / 48 / 60 | 像素字体原生 12px 网格 + 整数倍缩放，**非 12 倍数会塌成同一档** |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 | |
| 高度 | 0（平）/ 1（2px 偏移）/ 2（4px 偏移） | 投影统一从这套里取 |

**为什么字号只有 5 档**：`fixed_size = 12` + `FIXED_SIZE_SCALE_INTEGER_ONLY` 意味着
12→12px、20→24px、34→36px。写 14px 实际渲染成 12px，层级会悄悄塌掉。

### 6.4 对比度（WCAG 校验器实测）

`TEXT_DIM` 原为 `#7a849a`，在 `PANEL_2` / `PANEL_3` 上只有 3.6:1，**不达 4.5:1**。
改用 `#909bb4`（偏蓝、提亮），在最亮的 `PANEL_3` 上 4.86:1，全组合通过。

### 6.5 游戏感细节

| 手法 | 位置 | 作用 |
|---|---|---|
| 圆弧扇形 + 悬停放大 | 手牌 | 手里握牌的感觉，鼠标一挪就有反馈 |
| 闪烁光标 `█` | 终端命令行区 | 终端感 + 暗示"可以继续输入" |
| 绶带横幅 | 命中连携时 | 凑成连携的**正反馈**，一眼看到"赚到了" |
| 数值跳动 + 闪色 | 得分、预计分 | 变化能被"看见" |
| 悬停高亮 + 角饰点亮 | 奖励卡 | 选择题的交互反馈 |
| 稀有度色条 | 奖励卡顶部 | 一眼分辨品质 |

### 6.6 卡牌：正面是梗，右键翻到背面看插画

- **正面**：类型色条（饭=金 / 代码=青 / 玄学=紫 / 杂项=绿 / 专属=红）+ **梗名** +
  **梗注解（flavor，一行说清这张卡为什么好笑）** + 基础分 + Token。
- **背面**：该梗的完整插画（`assets/art/meme-*.png`，150×226，等比缩放，
  **整张图完整可见，不裁切、不留白**）。
- **右键卡牌**翻面。动画用 `scale.x` 压扁 1→0→1 配合轻微倾斜（±0.10 rad），
  0.42 秒，`TRANS_CUBIC / EASE_IN_OUT`，中途再点会从当前位置接着走而不是跳回。

> 为什么加翻牌：梗卡插画是竖版大图，塞进 150×226 的卡里会挤；
> 而正面如果只留图，梗名和梗注解就没地方写。拆成正反两面正好两个都要。

### 6.7 每关独立种子

每关开打时用 `rng.seed = run_seed + 关卡 id 哈希` 洗牌：

- **不同关卡的牌序必然不同**（回归测试断言 10 关的起手牌序互不相同）；
- **同一关重打时牌序可复现**（失败重打不会纯看运气，局内可以"背牌"）；
- `run_seed` 每局随机，所以同一关在不同局里又不一样。

### 11.3 三个关键处理

1. **透明底**：API 支持 `background: "transparent"`，卡面与图标类素材全部走这个参数，
   拿到的 PNG 带 alpha，直接贴到深色卡面上不会留白框。
2. **半身像预裁**：原图是 1024×1024 全身立绘，直接用 `STRETCH_KEEP_ASPECT_COVERED`
   放进横向小框会裁到腰、脸反而被切掉。`crop_arena_busts.py` 按"顶部 50% 高度 + 1.6:1 横带"
   预裁成 `*-bust.png`，UI 里直接用。
3. **边缘融合**：主角图自带另一套深蓝科技室背景，贴到场景上会露出一圈生硬矩形边。
   `blend_arena_hero.py` 做三步：整体往场景色混 30% → 径向 alpha 渐隐 → 渐隐带内压向场景色，
   贴上去就融进背景了。

### 11.4 接入方式

所有贴图经 `scripts/ui/art.gd`（`Art` 静态类）懒加载并缓存：

```gdscript
Art.card_tex(kind)          # 卡面类型插画
Art.hud_tex(kind)           # HUD 铭牌（level/token/compute/ai）；缺图返回 null，UI 降级纯文字
Art.item_bust_name(id)      # 道具半身像（模型道具 item-<id>-bust，技术道具 tech-<id>）
Art.tex("bg-arena")         # 背景
```

缺图不崩：`Art.tex()` 返回 null，UI 侧有降级（卡面画问号圆点，列表不显示图标，HUD 铭牌退化为纯文字）。
