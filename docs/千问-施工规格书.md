## 0. 一句话定案

**元代点茶 × 候汤机制。** 千问的水会越烧越开——连续出牌升温加伤，烧过头就「水老」打折还自伤，打一张「续水」把水温拨回一沸。她不是在爬阶梯，是在看火。青花只留在她手里那只执壶的釉面上，纸面是灰黄皮纸配松烟墨、朱砂印、花青。

### 为什么是元代（三朝对比）

| 方案 | 美术返工 | 机制返工 | 合计 | 裁决 |
|---|---|---|---|---|
| 锁宋 | 3.0d（立绘重画1.5d + 茶室背景0.5d + 器物0.5d + 卡框面板0.5d） | 0 | ≈3.0d | 否——宋无青花，唯一一张立绘与茶室全废 |
| **锁元** | 1.2d（立绘局部0.5d + 器物0.3d + 背景0.3d + 术语0.1d） | 0（末茶未绝） | **≈1.2d** | **采纳** |
| 锁明 | 0.7d | 2.6d（三泡递减 + 起手十张替换 + 重跑模拟） | ≈3.3d | 否——要弃三张有原文的卡，换一条未核实的引文 |

**元是唯一交集**：团茶要到洪武二十四年（1391）才罢造，元代点茶合法；青花在元代才成熟（景德镇至正型）。所以击拂、咬盏、沫饽三张最像工序的卡在元代**全部成立**——锁明才是要弃卡的方案。

## 2. 机制规格（`scripts/core/sts_combat.gd`）

一句话：**连续出牌升温，第 3–4 张吃 ×1.3；烧过 4 档即「水老」，本张结算后自伤 1；打「续水」把温度拨回一沸。她不是在爬阶梯，是在看火。**

| 项 | 值 | 落点 |
|---|---|---|
| 新增状态 | `var brew := 0`（0..4） | 文件头变量区 |
| 倍率表 | `[0.8, 1.0, 1.3, 1.3, 0.6]` | `_play_card_impl` 的 `step`/`slot` 同层加法 |
| 推进 | 数值牌结算后 `brew = mini(brew + 1, 4)` | `_play_card_impl:454` 结算尾部 |
| 水老 | `brew >= 4` 本张结算后自伤 1 | 同上 |
| 冷却 | `start_turn`: `brew = maxi(0, brew - 1)` | `:259` |
| 不清零 | `end_send` **不清** `brew` | `:528`（对照 `seq_streak = 0` 在 `:530`） |
| 关连段 | `var step := 0 if ai_id == "kweno" else STREAK_STEP * (seq_streak - 1)` | **两处同构**：`:454` 与 `preview_sequence:1033` |
| 预览同构 | 影子推演从**当前** `brew` 起步、逐张推进 | `preview_sequence:1005` |

**为什么关连段**：否则「连段 + 火候」两个同向奖励叠加，只是更强，不是不同。与 DeepSeek 的分界是 **`seq_streak` 每序列清零 vs `brew` 跨回合不清、可升降**——一次性连段 vs 可复位的水温周期。

### 辅助机制（P1，可延后）
- **沫饽**：`end_send` 时若 `brew` 停在 2..3（正好三沸），`block += 2`，日志「汤花咬盏」。奖励**停在对的温度**，而非烧到底。
- **茶末**：主动弃牌得 1 末，3 末→下一张攻击 +5 并清零。把「每回合 3 次弃 1 抽 1」从纠错手段改造成资源生产。

### 顺序可改写（必做，0.5d）
**不做拖拽，做「点两张换位」。** 执行序列就是手牌下标（`hand[0]` 是最左那张），所以：
```
开排序模式（复用 discard_mode 那套开关）
→ 点第一张 → 点第二张
→ combat.hand.swap(a,b)
→ _hand_views.swap(a,b)
→ _layout_hand(true)
→ _update_seq_preview()
→ 关模式
```
改动集中在 `arena.gd` 三个函数，**不碰 `sts_card_view.gd`**。

**为什么砍拖拽**：拖拽会踩三个坑（拖动中 `_layout_hand` 动画与悬停同触发、点击/拖拽阈值判定、换序后 `can_play` 整表刷新）。**半成品拖拽比没有拖拽更糟。**

### 30 秒可感知性（关键）
必须做两件，否则机制只能活在你嘴里：
1. **预览接 `brew`**：`preview_sequence` 已把每张牌的预计数值写在卡面上（`sts_card_view.gd:366 set_seq_value`）。接上后玩家**还没按发送**就能看到 6/10/3/0，点一下换序数字立刻重排——不用教程。
2. **四段茶汤条**（`arena.gd` HUD，0.15d）：每出一牌点亮一段，水色由深转浅，换茶归零。并且**显示下一张的倍率预览**（「下一张 ×1.3」），不是只显示当前档位。

| 续水 | SKILL | 1 | 格挡 +3 | 火候归零，护盾 +3 | 水老不可食——那就重烧。 | 同上「已上水老，不可食也」 |

**卡名 = 工序名 = 触发条件名，三者同构**；任一张抽掉机制就塌一个角。这就是「机制而非皮肤」的可验证判据。

- 急速收敛×3 → 候汤/击拂系
- 白米饭×3 → 茶末
- 熔断保护×2 → 续水/咬盏系
- 复读机×1 → 再注
- 并行×1 → 双注

`starter_deck_for()` 加 `kweno` 分支（现在只有 `chatppt` 分支，`sts_card_pool.gd:180`）。

## 4. 美术规格

### 4.1 卡框 = 元代书叶（蝴蝶装半叶）
- 版式：四周外栏 2px + 内栏 1px、天地头线 2px、右缘版心缝 1px、版心鱼尾双三角、画心四角界行各 1px
- 做法：离线程序生成 750×1130 两张（attack/defend 同版式、只换框线色），运行时仍是 1 个 `TextureRect`，**零新增 draw**
- **必须重标 5 个 rect**：`COST_RECT` / `NAME_RECT` / `LV_RECT` / `ART_RECT` / `SLOT_BADGE_RECT`（`sts_card_view.gd:29-33`）

建议值（@150，需目检）：
```
COST_RECT       = Rect2( 10, 10, 20, 20)
NAME_RECT       = Rect2( 40, 10, 62, 14)
LV_RECT         = Rect2(104, 10, 28, 14)
ART_RECT        = Rect2(  9, 32, 132, 184)   # 实测画窗 x[38,711]@750 → [7.6,142.2]，横向吻合
SLOT_BADGE_RECT = Rect2(122,  4, 18, 20)
```
重标步骤：出 750×1130 PNG → python 逐列/逐行统计暗像素占比找双栏与画窗边界 → 全部 ÷5 → 代入 → `--shot=arenalayout` 目检字位。

### 4.2 面板 = 立轴（`character_intro_panel.gd:449` 重写 `_draw_scroll`）
297×555 = 1:1.87 竖长（手卷是横长 1:5+，所以术语必须是**立轴**不是手卷）。8 次 `draw_rect` + 2 次 `draw_circle` + 2 次 `draw_line` + 纸纤维循环 + 1 个 Label（朱砂小印 26×26 内写「千问」）。

**核心升级点**：`_draw_scroll` 现在左右两条 9px 竖带 + 等距圆点，是「横披」不是「卷」，而且那串圆点**不是任何有谱系的青花纹样**——面试官问「这是缠枝莲还是折枝花」会当场空。改成真卷轴的轴：左端地杆（深圆柱 + 2px 高光 + 椭圆端帽）、右端包首、画心内距线、左缘内阴影让纸「靠」进画面。

### 4.3 终端 = 制帖（`ext_terminal.gd` + `intro_script.gd`）
```
制帖 :: 千问待客 · 四事
其一  涤器　汤瓶一　茶盏四　山泉涤之
其二  候汤　蟹眼初沸　鱼目有声
其三  击拂　茶末一钱　汤响松风
其四  奉客　举案齐眉　请
```
- **不敲代码**（那是 DeepSeek 的语义），**不念诗**（诗是引用别人的嗓子，会被追问「为什么用这首」）。敲「制帖」——和代码同构（可执行步骤），但语义是中国茶事的技法。
- **字符集严格禁用 `░▒▓` 与 ASCII 梯度**——那就是 DeepSeek 的照片感灰度流。改用线层 `─│┌┐└┘├┤┼` + 半块层 `▀▄▌▐` + 块层 `█` 只给瓷面高光 + 点层 `·` 飞白。硬边版画感，计白当黑，留白 ≥55%。
- **终端里不要画脸**：44×120 下面部只有约 10×8 格，这是分辨率硬上限。
- 配色：标题 `White`；「其一～其四」`DarkCyan`（花青）；工序名 `White`；释义 `Gray`；**「请」一字 `DarkRed`，全篇唯一朱色**。
- 节奏：加 `line_mode` 整行一次落、行间 200ms。**必须修的真实 bug**：`$chars += $l.Length` 按 UTF-16 code unit 计，中文 1 字算 1 但显示占 2 格 → 视觉打字速度翻倍。

### 4.4 Q 版（`chibi_rig.gd` 零改造）
9 件契约：`head`（**头饰必须并入，单独成件会走路落后**）/ `hair_b`（z=-1）/ `torso`（立领+肩+**袖根**）/ `arm_l` / `arm_r`（只留小臂+手，pivot 抬到肘）/ `skirt_a` / `skirt_b`（拖地下摆）/ `leg_l` / `leg_r`。

两个难点规避：
- **宽袖**：`W_ARM = 6.0` 是给细长头发条带的余量，宽袖是整块布旋转必开腋下。**把袖根併进 torso**，独立件只留小臂+手。Q 版看不出损失，省掉整个「袖口补洞」返工。
- **长裙遮腿**：**步态交给裙**——`skirt_b` 做 follow-through（横摆 ±5、旋转 ±6，复用 `W_SKIRT_A` 量级），腿只露 2–3px 脚尖点地。

**档位：B（idle + shake + attack，1.15d）。** 不做 walk/run——`ai_select.gd` 里 `_fill_portrait` 只播 idle、悬停播 shake，**walk/run 一次都没被调用**。

**必须解决的真问题**：默认流程走 `character_select_screen.gd`，**不经过 ai_select，Q 版调用点为 0**。修法：在选角界面左下挂一个 0.5 倍小立绘（`ChibiRig.setup("res://assets/art/rig/kweno")`、`scale (0.5,0.5)`、`position ≈ (24,700)`）。位置是算过的：介绍面板 rect 是 `(0,136,297,555)`（y 到 691），`START_BTN_POS` 是 `(1330,800)`，左下 297×200 是唯一空区。**演示视频里必须标注「此界面走 --oldmenu」**，否则就是第二个十秒翻车点。

## 7. 面试话术（30 秒，约 145 字，可背）

> 我给千问做的是一件事：把宋人看水的老规矩，变成她每回合要判断的火候。水越烧越开，牌打重了会伤自己——这是机制，不是皮肤。朝代只锁一个：元。点茶在元没死，青花在元才成熟，这是唯一交集。青花只留在执壶上，纸面是灰黄皮纸。代码是 AI 写的，但火候跨不跨回合、砍不砍连段是我定的。拖拽重排我没做完，现在是点两张换位。

**美术部分补三句**：

> 画面是 AI 出的，朝代是我定的。她头上那圈蕾丝荷叶边我否了——元代是包髻簪钗，AI 按西式软帽画。卡框的青花蓝我也换了，因为钴蓝只在釉下，纸面上只能用花青。判据就一条：这件器物、这个颜色，能不能找到谱系。

**最可能被追问穿的一句 + 怎么答**：

> **问**：「你这卡框是宋版书的鱼尾，你刚才又说锁元代——元代人不用这个版式吧？」
>
> **答**：不辩，直接交出规则和放弃项——「卡框我最后放弃了，没做鱼尾。整套只有一句话：机制建在水相这一层，它朝代无关（蟹眼、鱼目是水的物理反应，唐宋元明都在看）；命名和器物锁元，因为元是点茶未死、青花已成的唯一交集。宋版书叶是视觉总监的提议，它的朝代是宋，和元冲突，所以我砍了它。」

把「我知道冲突在哪，并且我为冲突付了代价」说出来，这题就从扣分变加分。
